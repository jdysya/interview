# LLM 服务：流式输出、缓存与成本控制

> 复习优先级：P1 · 整理与来源核验：2026-09-05

## 面试题：为什么模型服务吞吐很高，用户仍感觉慢？

**60 秒回答：** 用户延迟包含排队、检索、Prompt prefill、逐 Token decode、工具调用和网络传输。吞吐表示总体产能，首 Token 延迟与 Token 间隔决定交互体验。批处理增加吞吐时可能增加等待时间，需要在服务等级目标下评估。

## 请求路径中的优化

- 缩短无用上下文，稳定复用前缀，避免每轮重复注入全部工具说明。
- 对简单任务路由小模型；复杂任务按评测结果升级模型，记录路由误判。
- 对可复用内容使用缓存，缓存键包含模型、Prompt、语料版本和权限域。
- 流式发送增量事件，提供请求 ID、完成或失败信号；断线重连必须定义能否恢复。
- 为模型、工具、整任务分别设超时，避免一个环节无限拖延。

## 面试题：KV cache 与答案缓存有什么不同？

KV cache 保存注意力计算需要的中间状态；前缀缓存复用相同前缀的部分计算。答案缓存直接复用业务输出，需要额外判断新鲜度与语义适用性。KV cache 不是“模型永久记住了这段话”。

**资源估算：** FP16/BF16 权重可粗估为参数数量乘 2 字节，量化后还需算缩放因子、非量化层和运行开销。KV cache 随并发、序列长度、层数和 KV head 等因素变化；48GB 显存不等于能装满 48GB 权重后继续无限并发。

## 常见追问

- **SSE 比 WebSocket 好吗？** 单向增量输出常可用 SSE；双向实时通信可用 WebSocket，取决于协议需求。
- **缓存命中能证明回答正确吗？** 不能，缓存只复用已有结果。
- **降成本只选便宜模型吗？** 还要比较成功任务成本，过多重试可能更贵。
