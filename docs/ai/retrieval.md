# 混合检索、Rerank 与向量索引

> 复习优先级：P0 · 整理与来源核验：2026-09-05

## 面试题：有了向量检索，为什么还需要 BM25？

**60 秒回答：** 向量检索擅长语义相近，关键词检索对专有名词、错误码、表名和精确词更可靠。先并行取得候选集，再做融合和去重，最后用 Reranker 对有限候选精排。各阶段的代价和召回指标应分别评估。

## 融合与重排

BM25 和向量相似度不在同一量纲，直接加分可能失真。RRF 根据名次融合：某文档在每一路出现时贡献 `1 / (k + rank)`，其中 rank 从 1 开始，k 是平滑参数。RRF 的 k、候选窗口和最终 Top-K 不是同一个参数。

Reranker 通常联合编码 query 和 document，对候选排序更精细，但不能找回从未进入候选集的文档。先确认召回，再调重排。

## 面试题：HNSW 索引怎么权衡？

近似最近邻以一定召回损失换取搜索速度。提高搜索候选宽度通常增加召回和延迟；图连接度、构建参数影响内存、索引时间与质量。具体参数名称由向量库决定，应固定数据集测量 recall-latency 曲线。

## 追问与实验

- **换 Embedding 模型能直接沿用旧向量吗？** 通常不能，应重建索引，使用版本化路由逐步切换。
- **距离指标怎么选？** 按模型训练与文档建议；归一化向量的余弦与内积可有相同排序，但不能一概混用。
- **Top-K 越大越好吗？** 不是；会增加噪声、延迟、Token 和冲突证据。
- **怎么比较方案？** 固定问题与相关文档标注，分别测关键词、向量、融合、加重排后的 Recall@K、MRR 和端到端正确率。
