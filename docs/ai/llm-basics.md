# LLM 基础：从 Token 到模型选型

> 复习优先级：P0 · 整理与来源核验：2026-09-05

## 面试题：接入大模型前需要理解哪些基本概念？

**60 秒回答：** Token 是模型处理文本的基本单位，Token 数影响上下文预算和计费；Embedding 把内容映射为向量以支持检索。生成模型通常自回归地产生后续 Token，训练目标不等于事实核验。选型需要用自己的任务评测准确性、工具调用、延迟、成本和部署约束，不能只看参数量或榜单。

## 关键概念

| 概念 | 面试时应讲清的边界 |
| --- | --- |
| 上下文窗口 | 能接收的上限；不保证长文每处信息都能被可靠使用 |
| temperature / top-p | 影响采样；低温度不保证事实正确或跨平台绝对确定 |
| Embedding | 优化相似度表示，不负责直接生成答案；不同模型的向量通常不能混用 |
| 预训练 / SFT | 前者学习通用分布，后者适配指令与示例；都不能代替实时业务查询 |
| RAG / 微调 | RAG 提供可更新外部证据，微调改变行为模式；可组合使用 |
| MoE | 区分总参数与每 Token 激活参数；推理内存还受实际加载方式影响 |

## 面试题：为什么模型会幻觉？

输入证据不足、检索错误、知识过期、问题本身有错误前提，以及生成过程都可能带来不可靠内容。生产方案应要求证据引用、缺证据时拒答，对数字和规则用确定性程序校验，并在评测中单独统计无依据断言。

## 选型小实验

固定一组有答案与评分规则的业务问题，同时记录任务通过率、首 Token 延迟、完整响应时间、单次成功任务成本和失败类型。所有模型使用同样的输入、工具、超时和重试预算。长文本、结构化输出、中文及多轮任务分别统计，避免平均分掩盖短板。

## 常见追问

- **RAG 能完全消除幻觉吗？** 不能，取回文档与正确使用文档是两件事。
- **微调适合更新每天变化的库存吗？** 不适合；库存应查询业务服务。
- **参数更多一定更好吗？** 不一定，必须在具体质量与资源约束下比较。
