# RAG 全链路与失败定位

> 复习优先级：P0 · 整理与来源核验：2026-09-05

## 面试题：如何设计一个企业知识库问答系统？

**60 秒回答：** 离线侧负责文档解析、去重、分块、元数据和权限标记、索引更新；在线侧完成鉴权、检索、重排、证据组织和答案生成。文档必须保留来源、页码或段落位置、版本和租户信息。评估时把“有没有召回正确证据”和“有没有依据证据回答”分开。

## 从数据到答案

1. 解析 PDF、HTML、Markdown，保留标题层级、表格和页码。扫描页需 OCR，不能把解析失败误判为检索差。
2. 按语义结构切块，必要时设置重叠；块大小用真实问题验证，不存在固定万能值。
3. 每块记录 `document_id / chunk_id / version / source / acl`，原文与向量可分别存储。
4. 查询时先绑定用户权限，再进行关键词与向量召回。重排后根据 Token 预算选取证据。
5. 输出答案和证据定位；证据不足时说明缺口，不补造出处。

## 面试题：回答不准，先改 Prompt 吗？

| 现象 | 优先排查 |
| --- | --- |
| 库里根本没有答案 | 数据覆盖、采集周期、文档权限 |
| 原文有答案却未召回 | OCR、切块、过滤条件、Embedding、召回深度 |
| 召回了但没进入最终上下文 | 重排、去重、预算截断 |
| 证据完整却答错 | Prompt、模型、冲突证据处理、计算步骤 |
| 答案正确但引用错误 | 引用绑定、chunk ID 校验、渲染映射 |

## 常见追问

- **删除文档怎样同步索引？** 记录版本和删除标记，删除全部关联块，清理缓存；切换索引版本后再回收旧版本。
- **同一问题不同用户为何答案不同？** 检索范围受 ACL 约束，缓存键也必须包含权限范围或版本。
- **长上下文能替代 RAG 吗？** 小语料可直接放入上下文；大语料、权限、更新、成本和可溯源仍需要检索设计。

## 易错点

只在返回答案后做权限过滤已经太晚；未授权文档可能已进入模型或日志。把所有 PDF 每页硬切一次，也容易拆断表格和跨页论证。
