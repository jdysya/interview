# 网络、HTTP 与服务治理

> 复习优先级：P1 · 整理与来源核验：2026-09-05

## 面试题：TCP 可靠传输是否代表业务请求不会重复？

**60 秒回答：** TCP 在连接内提供有序字节流和重传机制，但应用可能在服务端已处理、响应丢失后重试，造成重复业务动作。网络可靠性与业务幂等是不同层次，仍需请求标识、超时与状态查询。

## HTTP 基础

HTTP 方法有各自语义，GET 应是安全的读取；PUT 的目标语义通常具有幂等性，POST 也可以通过业务设计支持幂等。幂等描述业务效果，不保证每次响应字节完全一样。HTTP/2 的流复用不等于消除了 TCP 层队头阻塞；HTTP/3 使用 QUIC，仍需讨论应用依赖与拥塞。

## 面试题：接口突然变慢怎么排查？

将总时间拆成客户端、网关、应用排队、线程/连接池、数据库、缓存、远程服务等部分。按 Trace 找慢 span，再结合指标看单点与整体。平均延迟正常但 P99 恶化常提示尾延迟问题，不能只看平均值。

## 服务治理

超时预算应沿调用链分配；重试仅针对可恢复错误，结合幂等和退避。限流限制进入系统的流量，熔断减少对异常依赖的调用，降级定义在资源不足时返回什么可接受结果。健康检查与业务可用性也不完全等同。

## 常见追问

- **为什么每层都重试会出问题？** 尝试次数相乘并扩大故障时流量。
- **429 与 500 一样重试吗？** 应按错误、Retry-After 和服务契约处理，且有上限。
- **心跳正常就代表消息送达吗？** 不能；连接存活、服务端收取和客户端业务处理是不同确认点。
