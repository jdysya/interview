# JVM、GC 与线上排障

> 复习优先级：P1 · 整理与来源核验：2026-09-05

## 面试题：Java 内存溢出怎么定位？

**60 秒回答：** 先确认是哪类资源耗尽，再结合监控、GC 日志、线程信息和必要的堆转储分析。堆、Metaspace、Direct Memory 或线程数量问题的排查路径不同。容器被 OOM Kill 也不一定有 Java OutOfMemoryError。

## 排查顺序

1. 确认时间线、发布变更、请求量、内存与 CPU 趋势和容器限制。
2. 判断活跃对象持续增长，还是分配速率突增、配置不合理或外部资源未释放。
3. 查看 GC 频率、暂停和回收后占用，再分析 dominator tree、引用链与大对象。
4. 验证假设后修复，使用相同负载比较恢复情况；不要只调大堆后就关闭问题。

## 面试题：G1 和低延迟 GC 怎么选？

围绕吞吐、暂停目标、堆大小、CPU 预算与 JDK 支持比较。G1 把堆划分为 Region，垃圾回收仍有暂停阶段。任何收集器都不是“无停顿”，低暂停也可能需要额外 CPU 或内存。默认值和功能取决于 JDK 发行版与版本。

## 常见追问

- **CPU 100% 一定是 GC 吗？** 也可能是死循环、热点计算、锁竞争或过多线程；用 profile 和线程栈定位。
- **堆转储能随时做吗？** 可能造成暂停、磁盘压力，并包含敏感业务数据；按运行环境安排采样和保护。
- **类加载为什么要双亲委派？** 有助于基础类唯一性和隔离，具体加载器体系可按框架需求扩展。

## 演练

分别制造无界集合增长、线程池队列堆积、连接未关闭三种问题，比较它们的监控信号。面试描述“发现了什么证据，排除了什么假设，如何验证修复”，比背命令清单更有说服力。
