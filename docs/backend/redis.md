# Redis：缓存问题、持久化与分布式锁

> 复习优先级：P0 · 整理与来源核验：2026-09-05

## 面试题：穿透、击穿、雪崩怎么区分？

**60 秒回答：** 穿透是反复访问不存在的数据；击穿是热点 key 失效带来集中回源；雪崩是大量缓存同时失效或缓存服务故障造成后端过载。分别考虑输入校验/空值缓存、单飞重建/逻辑过期、过期时间打散/限流降级，并保护数据库的容量边界。

## 机制与边界

空值缓存需要较短 TTL 并处理后续新增；Bloom Filter 有误判，应和查询语义配合。逻辑过期允许返回旧值，只适用于业务接受陈旧结果的场景。缓存系统恢复时也需要限制重建并发。

RDB 保存时点快照，AOF 记录写命令相关持久化信息；恢复窗口、fsync 策略与故障模型影响数据耐久性。Redis 并非“所有工作都只有一个线程”，应区分命令执行与后台/IO 工作及版本配置。

## 面试题：SET NX PX 就实现了可靠分布式锁吗？

它是单实例租约锁的基础，还需要不可猜测的持有者 token，并原子地比较 token 后释放。锁到期、进程长暂停、网络分区、复制切换都可能让旧持有者继续工作。对强一致资源可使用 fencing token，但前提是资源侧实际校验并拒绝旧 token。

## 常见追问

- **Watchdog 可以保证永不重复吗？** 不能，续租也是网络操作，仍需业务幂等或数据库条件更新。
- **锁与唯一索引有什么关系？** 锁减小并发竞争，唯一约束保证落库不变量，两者职责不同。
- **删锁直接 DEL 为什么危险？** 可能删除已经属于另一请求的锁，必须验证所有权。
- **热 key 怎么办？** 本地缓存、副本/分片策略、请求合并和限流按读写语义选择，不能无条件拆散同一业务值。
