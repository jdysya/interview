# 回答方法与项目复盘

## 基础题：定义、机制、边界、例子

先用一句话回答，再解释关键机制，最后补一个反例或业务使用场景。例如回答 Redis 锁：先说明租约与互斥目的，再讲 NX、TTL、token 校验释放，接着指出锁过期与故障切换风险，最后落到数据库唯一约束或业务幂等。

## 算法题：先说不变量

确认输入和返回约定，给出暴力解与复杂度，再说明优化依据。编码前明确区间定义、去重规则、溢出与空输入。写完手工验证至少一个常规案例和一个能击中边界的案例。

## 场景题：七个步骤

1. 需求：谁使用、成功条件、延迟/一致性/成本约束。
2. 估算：日均与峰值、读写比例、数据增长，所有假设明确标注。
3. 接口：输入、输出、鉴权、幂等和错误语义。
4. 数据：主键、唯一约束、索引、版本、状态。
5. 链路：同步与异步边界、权威数据源。
6. 失败：超时、重复、乱序、并发、崩溃、补偿。
7. 验证：指标、压测、故障注入、回滚或恢复方式。

## 项目经历：陈述可验证的贡献

讲清问题、约束、本人负责的模块、为何选择该方案、如何验证及剩余风险。没有做过的机制应称为改进方案，未测量的收益不能编成百分比。避免仅罗列“高并发、分布式、Agent、多模态”等词。

## 三个通用追问

- 哪个状态或约束保证你的方案正确？
- 系统在最不利的时刻崩溃会发生什么？
- 你用什么证据证明它比更简单的方案好？
