# 通用面试学习路线

先建立岗位对应的基础体系，再练具体问题和通用场景。不要从某个个人项目倒推出整个题库，也不把“看到过一个术语”算作学会。

## Java 后端路线

语言与集合 → JMM、锁与线程池 → JVM → MySQL 索引/事务/日志/锁 → Redis 数据结构/持久化/缓存 → Spring、MyBatis → 网络、操作系统与排障 → 消息与分布式设计。

先从 [线程池详解](../backend/jmm-threadpool.md)和 [缓存一致性详解](../backend/cache-outbox.md)看一篇内容应该展开到什么程度。其他模块已有内容的深度不一，[覆盖审阅](./coverage-audit.md)列出了待补机制。

## AI 应用路线

模型输入输出和生成机制 → Prompt 与结构化输出 → 文档处理、Embedding、ANN → 混合检索、重排与证据组织 → RAG 评测 → 延迟、成本、流式服务与权限。

读 [RAG 检索详解](../ai/rag-lab.md)时，至少能手算一次排名融合、解释一次切块反例，并区分“召回不到”和“召回了但没进入上下文”。不要求先拥有某个业务项目。

## Agent 路线

Agent 与 Workflow → 一次工具调用 → 决策循环和停止条件 → 状态与记忆 → 有依赖的调度 → 超时、取消和副作用 → 任务评测与安全。

[工具调用详解](../agent/tool-contracts.md)解释模型意图、宿主执行、MCP 协议和业务身份的分工。先理解这些边界，再进入框架 API 和多 Agent；不能用框架名称替代理解。

## 算法与场景设计

算法按题型学习：先证明不变量，再写代码和边界测试，随后做变式。系统设计从短链、聊天、限流、通知、上传下载、知识库等通用场景建立方法；本站目前只覆盖其中部分，不能把该列表当成已有题解清单。

每道设计题至少回答需求是什么、为什么选这个数据模型、容量怎样估算、关键请求走哪条链路，以及故障时会损失什么。具体教学案例是练习材料，不是简历经历。

## 一次学习的验收

能独立回答核心问题，能推导一个具体例子，能解释一个反例，能说清替代方案与代价。存在可运行示例时再运行验证；没有执行过的实验不写成自己的实测经验。

[自测](../practice/README.md)可辅助记录薄弱项，但自评分不等于客观能力评估。图示、模拟面试和练习面板都只是内容学习的辅助。
