# 🔬 项目深挖与可复现实验

这里把基础机制连接成完整设计。所有案例都是通用教学方案，不包含公司内部代码、平台名称、凭据、个人信息或未经证实的落地成绩。

| 项目 | 主线问题 | 应掌握的证据 |
| --- | --- | --- |
| [数据库查询 Agent](./database-agent.md) | 从意图定位到受控执行 | 工具契约、SQL 口径、权限、结果引用 |
| [库存预占与释放](./inventory-reservation.md) | 并发状态转换与业务不变量 | 条件更新、幂等键、异常矩阵 |
| [审批工单一致性](./approval-consistency.md) | 远端副作用与本地关联 | 持久意图、查证、撤销补偿 |
| [实验运行说明](./experiments.md) | 证明机制而非只讲方案 | Java / Python 测试与局限 |

## 阅读顺序

先说明需求与非目标，再写不变量、数据和接口模型，最后推导正常流程与每个失败窗口。每个项目至少准备一份可画出的流程、一段关键代码和一个失败测试。

## 表述分层

“已实现”要对应仓库代码和运行记录；“已验证”要说明测试环境与覆盖范围；“设计方案”应明确尚未接入的系统。教学示例不能自动转化成简历里的线上成果，吞吐、提升比例、节省费用和用户量都必须有真实依据。
