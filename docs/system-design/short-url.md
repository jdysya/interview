# 场景设计：短链系统

> 复习优先级：P0 · 整理与来源核验：2026-09-05

## 题目与需求澄清

设计一个生成短链接并跳转到原网址的系统。先确认创建量、访问量、有效期、自定义后缀、是否允许修改、访问统计与滥用治理。以下是设计练习，容量数字是计算示例。

## 60 秒方案

创建服务校验 URL 并生成唯一短码，将映射持久化；跳转服务先读缓存，再查数据库，检查状态与过期时间后返回重定向；访问事件异步进入统计链路。读远多于写时，重点保护热点跳转和数据库回源。

## 容量与数据模型

假设每日新增 100 万条，平均创建速率约 11.6/s；峰值另根据业务估计。每天访问 1 亿次则平均约 1157/s，不能拿日均当容量上限。存储估算要计入 URL 长度、索引、副本与保留周期。

核心表：`id、short_code(unique)、original_url、owner_id、status、expires_at、created_at`。短码可用 ID 的 Base62 编码或随机字符串；随机码需唯一约束和碰撞重试，截断 Hash 也会碰撞。Base62 是编码，不是加密。

## 关键权衡

- 可变目标通常避免不可控的永久重定向缓存，明确 301/302 等状态语义。
- 热点短链缓存、未命中空值缓存、限流与单飞回源配合使用。
- 只允许合适的 URL scheme，防止危险链接；若服务端抓取目标预览，还需处理 SSRF。
- 点击统计可异步且最终一致，跳转主链路不等待统计聚合。

## 面试追问

- **短码能否猜测？** 自增编码可枚举，是否有影响取决于内容访问规则；短码不应承担鉴权。
- **删除怎么生效？** 持久化状态、失效缓存，明确传播时间。
- **相同长链接要返回相同短码吗？** 先确认是否按用户、有效期和统计目的区分。

## 验证

压测冷热混合访问、单热点、无效码攻击；故障注入覆盖缓存宕机、数据库慢查询和创建重试。验收关注重定向正确性、P95 延迟、错误率与过载下的数据库保护。
