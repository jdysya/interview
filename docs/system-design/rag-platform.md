# 场景设计：多租户知识库平台

> 复习优先级：P0 · 整理与来源核验：2026-09-05

## 题目与需求澄清

面向多个团队的企业知识库，支持文档导入、更新、权限与问答引用。明确租户规模、文档类型、更新周期、延迟目标、来源可见性及删除时效。

## 60 秒方案

控制面管理用户、租户、文档版本和导入任务；异步数据面负责解析、切块与索引；在线问答服务在授权范围内召回、重排并生成带引用的答案。原始文档、块、索引和缓存都绑定版本，支持可验证的更新与删除。

## 核心模型与流程

文档记录包含 `tenant_id、document_id、version、status、acl、source`；任务记录包含阶段、错误、重试次数和产物引用。导入状态可为排队、解析、索引、可用、失败，未完成的新版本不覆盖旧的可用版本。

使用新索引版本完成构建和抽样验证，再切换读取别名或路由。删除需要撤销可见性、删除关联块并清理缓存，留意后台任务不得把已删除版本重新写回。

## 安全与成本

检索前约束租户和 ACL，不能靠 Prompt 要求模型“不要回答其他租户”。语义缓存也应按权限域隔离。向量、日志、备份同样属于数据治理范围。

按租户设置并发、Token、导入体积和检索配额。按任务难度选择模型，统计成功问答成本；仅统计模型输入输出费用会漏掉解析、重排和存储开销。

## 追问与验收

- **权限刚撤销，旧缓存还能用吗？** 缓存键应包含权限版本或在权限变更时失效，并明确传播窗口。
- **能直接执行文档中的指令吗？** 文档是不可信输入，不能赋予工具权限。
- **如何判断 RAG 改进？** 固定题集和语料，对召回、引用正确、拒答与越权案例分层验证。

验收覆盖跨租户检索、文档更新/删除竞态、OCR 失败、超长文档、任务重放，以及证据不足时的回答。
