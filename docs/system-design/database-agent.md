# 场景设计：数据库查询分析 Agent

> 复习优先级：P0 · 整理与来源核验：2026-09-05

## 题目与目标

用户描述业务问题，系统结合代码定位表和数据源，生成只读 SQL、执行并解释结果。可能存在逻辑表、分库分表、多个环境与不同数据权限。下面是通用架构，未使用任何内部平台凭据或非公开数据。

## 60 秒方案

Agent 负责意图澄清和步骤编排；Skill 固化定位代码、解析配置、路由、查 Schema、SQL 校验与结果验收的方法；MCP Server 封装配置平台、路由平台和数据库平台的已授权 SDK/API。SQL 由模型提出，但执行权限和约束由确定性服务控制。

## 工具边界

| 工具能力 | 输入 | 输出 |
| --- | --- | --- |
| 代码定位 | 仓库、业务标识 | 文件位置、逻辑表和证据 |
| 数据源解析 | 配置引用、环境 | 受控 datasource_id，不输出密码 |
| 分片路由 | 逻辑表、分片键 | 目标物理表/库或缺失条件 |
| Schema 查询 | 数据源、表 | 字段、索引、类型与注释 |
| SQL 校验 | SQL、查询上下文 | AST 校验结果、预计范围、限制 |
| 查询执行 | 校验后的查询 | 样本、行数、截断标记、结果引用 |

## SQL 执行保护

使用只读凭据；通过 AST 分析限制语句类型、多语句、危险函数与跨库访问；强制时间与行数上限，必要时验证执行计划。仅检查 SQL 是否以 SELECT 开头不够，因为 CTE、函数、注释与方言都影响语义。

大结果保存为结果文件或资源，模型读取统计和必要片段。最终答案附 SQL、数据源、时间口径、是否截断和来源证据。分片键缺失时先评估全路由代价，不擅自遍历所有生产库。

## 常见追问

- **为什么 SDK 能拿到配置？** 它以已有身份请求平台服务；JAR 中是客户端代码，不是动态配置本身。
- **Skill 还是 Agent？** 若已有宿主承担决策，可称“基于 Skill 与 MCP 工具扩展的查询 Agent 能力”；独立运行框架则需说明自己的状态与执行机制。
- **结果对但 SQL 错能算通过吗？** 不能，需检查权限、口径、范围和可复现性。

## 验收

准备金标准 SQL 与结果样本，测试错误表名、字段漂移、缺分片键、超时、超大结果和越权请求。执行成功率、语义正确率、扫描成本与权限违规分开统计。
