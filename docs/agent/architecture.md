# Agent、Workflow 与执行框架

> 复习优先级：P0 · 整理与来源核验：2026-09-05

## 面试题：什么场景需要 Agent？

**60 秒回答：** 当任务的步骤和工具选择需要根据运行结果动态决定时，可用 Agent。步骤明确、稳定且要求可控的任务优先采用 Workflow。实际系统常在确定性流程里嵌入少量模型决策节点，既利用模型判断，也保留状态、预算和错误处理。

## 执行模式比较

| 模式 | 适用情形 | 主要代价 |
| --- | --- | --- |
| 固定 Workflow | 审批、数据清洗等流程明确的任务 | 变化需要改流程 |
| ReAct 风格循环 | 根据观察决定下一个工具 | 循环失控、重复调用、错误累积 |
| Plan-Execute | 可拆分的长任务，需要里程碑 | 计划过时，需要重规划 |
| 多 Agent | 子任务可独立完成，角色/上下文有明确边界 | 通信、协调、重复工作与成本 |

模型负责提出动作，运行框架负责校验、执行、记录观察、更新状态和终止。Plan-Execute 可以由同一个模型分阶段执行，不天然等于多 Agent。

## 一个最小执行框架应有哪些字段？

`task_id、status、goal、step、budget、messages、artifacts、tool_runs、error`。每轮先检查取消和预算，再请求决策；工具执行后写入结构化结果，最终根据验收条件结束。状态记录应包含可审计的动作和结果，不依赖保存模型私有思维链。

## 常见追问

- **什么时候停止？** 验收通过、无法推进、触及时间/费用/步骤限制，或用户取消。
- **Reviewer 一定能发现错吗？** 不一定，同源模型可能有相关错误，应使用测试、外部证据和确定性检查。
- **如何证明多 Agent 有价值？** 同预算比较单 Agent 与多 Agent 的完成率、延迟、成本；不能只展示角色数量。
