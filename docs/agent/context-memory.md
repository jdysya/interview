# 上下文工程与短期、长期记忆

> 复习优先级：P0 · 整理与来源核验：2026-09-05

## 面试题：工具返回很多内容，是否要等上下文满了再压缩？

**60 秒回答：** 不必。可以在工具结果进入上下文前做结构化提取、分页和体积控制，大结果保留原件并返回引用；同时对历史消息按需要压缩。压缩阈值只是策略之一，运行时应优先保留目标、约束、当前状态、关键证据、未解决问题与最近相关动作。

## 三种存储边界

| 类型 | 保存什么 | 典型寿命 |
| --- | --- | --- |
| 工作上下文 | 当前模型真正看到的消息与证据 | 一次调用/当前任务 |
| 任务状态与 checkpoint | 计划、工具状态、游标、产物引用 | 可跨进程恢复 |
| 长期记忆 | 经筛选的偏好、事实、历史决策与来源 | 跨会话，可更新或删除 |

长期记忆可结合关键词与向量检索，召回后仍需权限检查、冲突消解和新鲜度判断。数据库持久化不等于内容会自动进入模型上下文。

## 工具结果压缩例子

SQL 返回一万行：原始结果保存为带有效期的结果文件；当前上下文放入列结构、总行数、必要统计、若干样本与 `result_id`。后续工具按 ID 查询所需区间。样本应标注采样方式，不能把前十行当作整体分布。

## 常见追问

- **摘要丢了细节怎么办？** 保留原件、可追踪引用和定向读取能力；摘要不是唯一事实来源。
- **所有工具记录都可以删吗？** 不可；调用与结果应保持协议配对，副作用记录和待解决异常要保留。
- **如何防止错误长期记忆污染？** 写入门槛、来源与时间标注、用户纠错、版本与删除机制。
- **checkpoint 是记忆检索吗？** 不是，前者恢复执行状态，后者按任务找到相关历史内容。
