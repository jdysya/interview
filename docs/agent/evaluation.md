# Agent 评估、Trace 与失败归因

> 复习优先级：P1 · 整理与来源核验：2026-09-05

## 面试题：Agent 最后说“完成了”，怎样确认它真的完成？

**60 秒回答：** 根据外部可验证的最终状态验收，例如文件是否存在且内容正确、测试是否通过、工单是否创建并关联，而不是只看最终文本。保存任务级 Trace，记录模型调用、工具参数、延迟、重试和产物；再按失败位置归因。

## 评测设计

每个用例包含输入、初始环境、权限、预算、成功条件和清理方式。模拟工具适合低成本回归，沙箱集成适合发现真实接口与环境问题，两者均需保留。

| 失败层次 | 例子 | 诊断证据 |
| --- | --- | --- |
| 理解 | 误解时间范围 | 用户输入、计划、生成参数 |
| 规划 | 漏了分片路由 | 计划与实际步骤 |
| 工具选择 | 使用更新接口完成查询 | 工具名、契约与授权结果 |
| 参数 | 时间单位错或表名不存在 | 校验器反馈、Schema |
| 执行 | 上游超时或缺依赖 | 状态码、日志与重试 |
| 验收 | 任务未完成却宣称成功 | 最终产物、独立检查 |

## 常见追问

- **看成功率还不够吗？** 还要看重复执行稳定性、越权调用、预算超限、P95 延迟与成功任务成本。
- **多跑几次取最好结果可以吗？** 可以报告 pass@k，但要同时报告预算；这不同于一次运行的可靠性。
- **Trace 是否保存所有原文？** 按需求脱敏与限制保留期，通常可存结构化摘要、哈希和产物引用。
- **新版本怎么上线？** 在固定回归集、关键安全用例和灰度环境中验证，再扩大覆盖；保留模型、Prompt、Skill 与工具版本。
