# MCP、工具契约与授权边界

> 复习优先级：P0 · 整理与来源核验：2026-09-05

## 面试题：MCP 和 Function Calling 有什么区别？

**60 秒回答：** Function Calling 是模型提出结构化调用的能力；MCP 是宿主/客户端与外部服务交换工具、资源等能力的协议。宿主可以把 MCP 工具转换为模型的工具定义，再路由调用。MCP Server 本身可以是普通程序，通过内部 SDK 或 API 获取真实数据。

## 工具设计

一个可靠工具应说明用途、输入结构、返回结构、错误类型、分页与数据上限。数据库查询工具可接受受控的数据源 ID、已校验 SQL 和行数上限；登录身份、凭据和权限由服务端提供，不接受模型任意声明。

工具返回应区分：成功但结果为空、参数错误、无权限、限流、上游超时与部分结果。大输出保存为可定位的文件或资源，只返回摘要、样本、行数与资源引用。

## 版本说明

本页对照 **MCP 2026-07-28** 规范。该版工具发现包含分页/缓存等契约，具体 SDK 的支持情况应单独确认。旧版握手或示例代码不能未经核对直接称为当前规范；调用示例应声明协议版本并优先使用匹配 SDK。

## 常见追问

- **SDK 为什么能查到数据？** SDK 封装请求、签名或鉴权和反序列化，数据仍来自其访问的服务；不是 JAR 自带业务数据库。
- **Stdio 与 HTTP 怎么选？** 本地进程集成常用 Stdio；远程服务可采用协议支持的 HTTP 传输，需处理身份与网络边界。
- **Tool 的只读标记能保障安全？** 标记是描述，权限与只读约束必须由运行时和后端执行。
- **HTTP 授权与本地凭据完全相同吗？** 不同；必须按对应传输和规范实现，避免直接转发不属于目标资源的 Token。

## 易错点

“提供了一个 MCP Server”不等于“实现了完整 Agent”；还需要宿主中的决策循环、状态管理和任务验收。
